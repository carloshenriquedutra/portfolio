People Analytics · raw to Gold

Business problem

A new People Analytics domain needed a dependable path from fragmented source records to reusable analytical models.

My contribution

I designed the cloud foundations and delivery flow, separating ingestion, source conformance, and analytical modeling. The path to Gold models continues to evolve.

Tools and methods

BigQuery · Dataform · Cloud Composer · Cloud Run · Terraform

Engineering decisions

Store prepared results and organize data by date

The challenge: Reading the entire history for every query can make analysis slower and more expensive. Reference records and event records also have different update needs.

Options considered: Calculate results for each query, store everything the same way, or organize each dataset according to how it is used.

My choice: Store reference records in tables and separate large volumes of events by the date they happened. Group records by fields frequently used to filter or connect data.

Benefits and limits: Queries can read only the dates they need. Stored results take up space and must be updated.

When to reconsider: Query costs increase, data needs more frequent updates, or teams change how they query it.

Organize data before applying business rules

The challenge: Source systems use different formats and names. Mixing data cleanup with business calculations makes each analysis repeat the same work.

Options considered: Provide data as it arrives from source systems, or separate its preparation from the calculations used in analysis.

My choice: Preserve incoming data, correct formats and remove duplicates in a separate step, then build tables around business questions.

Benefits and limits: There are more steps to maintain, but each has a clear purpose and can be checked separately. Prepared data can be reused across analyses.

When to reconsider: Source systems start sending data in a different form, or an analysis needs the original record.
